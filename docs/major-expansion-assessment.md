# 第二专业扩展评估（2026-09-15）

| 能力 | 结论 | 依据 / 缺口 |
| --- | --- | --- |
| 同一院校多个专业 | 支持 | `academic_schools` 独立于专业；招生计划唯一键包含 `year/province_slug/major_slug/school_slug/training_site`。 |
| 不同专业不同招生计划 | 支持 | `admission_offerings` 已带 `major_slug`，前台查询按完整范围过滤。 |
| 不同专业不同考试科目和考纲 | 支持 | 招生计划保存科目数组；`syllabus_points` 主键与查询均包含年份、省份和专业。 |
| 专业切换入口 | 不支持 | 公开数据可发现多个已发布范围，但院校目录目前只显示专业名称，没有专业选择控件。 |
| 院校 × 专业 SEO 页面 | 部分支持 | URL、运行时 title/description/canonical 已含专业和院校；纯 SPA 尚未为每个组合预渲染独立 HTML。 |
| 后台按专业筛选维护 | 部分支持 | 编辑表单和表格有 `major_slug`，但列表没有专业筛选器，年度复制仍写死 `computer-science`。 |
| 专业间复用公共资源 | 支持 | `resources` 不绑定专业，通过 `canonical_topic` 与各专业考纲匹配；相同主题可复用同一资源。 |

下一阶段建议：先增加公开专业选择器和后台专业筛选，把年度复制的专业参数改为管理员显式选择；随后选择一个资料完整的第二专业做小批量试录，并为组合页增加预渲染或静态生成。无需改变现有四段 slug 或拆分资源表。
